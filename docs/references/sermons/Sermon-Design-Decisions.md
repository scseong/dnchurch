# 소망교회 Sermon 섹션 — 디자인 의사 결정 기록

이 문서는 mockup (`ChurchSermonAll.jsx`)과 구현 프롬프트 (`Sermon-Implementation-Prompts.md`)에 도달하기까지의 맥락과 결정 사유를 기록합니다. 향후 비슷한 상황에서 참고하거나, 새로 합류하는 사람이 "왜 이렇게 만들었는가"를 이해할 수 있도록.

---

## 0. 배경

기존 코드베이스에 이미 어느 정도 구현이 되어 있던 상태에서, Sermon 섹션 5개 페이지의 UI/UX를 다시 설계하는 작업이었습니다. 목적:

- 디자인 일관성 강화
- 모바일/PC 통일성
- 도메인(교회 사이트, 한국어, 설교 컨텐츠) 적합성
- 실제 DB 스키마(`sermons`, `sermon_series`, `sermon_resources`)에 맞춤

작업 단위는 React 단일 파일 mockup. 단일 파일을 반복 갱신하면서 빠르게 시각 확인 → 피드백 → 수정 사이클을 돌렸습니다.

---

## 1. 진화 과정 요약

작업은 크게 5단계를 거쳤습니다.

**Phase 1: 메인 페이지 (List)**
초기 V1-V4 까지 메인 페이지(이번 주 설교 + 최근 설교)의 시각적 톤을 잡았습니다. 이 단계에서 도메인 어휘(말씀/설교/시리즈), beige + navy + gold 톤, 한국어 타이포그래피 기준이 잡혔습니다.

**Phase 2: 상세 페이지**
YouTube 스타일의 영상 좌 + 사이드바 우 패턴을 채택했습니다. 시리즈에 속한 설교는 사이드바에 회차 목록을 표시하고, 단독 설교는 같은 설교자의 다른 설교를 표시하는 분기.

**Phase 3: 추가 페이지 (전체 설교 / 모든 시리즈 / 시리즈 상세)**
한 도메인에서 사용자 동선을 완결시키기 위한 3개 페이지가 추가됐습니다.

**Phase 4: 통합 + 1280px**
다섯 페이지가 별도 파일이었던 것을 단일 파일로 합치고, 페이지 max-width를 1280px로 확장했습니다. 좌측 사이드바 필터 패턴을 도입.

**Phase 5: 디테일 다듬기**
사용자의 7개 + α 피드백을 두 차례에 걸쳐 반영. 캐러셀, 시리즈 메타 카드, 검색 피드백, 진행 표시 등 굵직한 변경이 이 단계에서 이뤄졌습니다.

## 2. 주요 의사 결정

### 2-1. 페이지 max-width: 960 → 1280px

**문제**
사용자가 반복적으로 지적: "디바이스가 커질수록 여백이 많아진다" "UI 밸런스가 맞지 않는다".

**선택지**
- A: 960px 유지 (보수적, 모바일 호환성 강조)
- B: 1280px로 확장 (와이드 디스플레이 활용)
- C: full-bleed 1440px+ (콘텐츠 사이트는 부담)

**결정: B (1280px)**

이유:
- 데스크톱 사용자 비율이 높은 도메인 (교회 컨텐츠는 가족 단위 시청, TV/와이드 모니터 사용 빈도 있음)
- 좌측 240px 사이드바 + 우측 결과 영역이 한 화면에 자연스럽게 들어가는 폭
- 캐러셀이 4-5개 카드를 한 번에 보여줄 수 있는 폭

**부작용 / 대응**
- 좁은 데스크톱(1366px 등)에서 좌우 여백이 작음 → padding 56px로 안정성 확보
- 모바일은 별도 (max-width 무시, 16px padding)

---

### 2-2. 최근 설교: 그리드 → 캐러셀

**문제**
초기 구현은 3x3 그리드 + 더 보기 카드였음. 사용자 피드백:
- 페이지 height가 너무 길어짐
- 메인 페이지에서 다른 섹션까지의 동선이 멀어짐
- 모바일에서 height 일관성 깨짐

**선택지**
- A: 그리드 행 수 줄임 (2행)
- B: 캐러셀 (가로 스크롤)
- C: 페이지네이션 미리보기 (탭형)

**결정: B (캐러셀)**

이유:
- 메인 페이지는 "탐색 시작점" 역할 → 한눈에 들어와야 함
- 캐러셀은 무한 확장 가능 (RECENT_SERMONS 8개 → 더 늘어도 OK)
- 모바일은 자연스러운 가로 스와이프 패턴
- "더 보기" 링크가 전체 설교 페이지로 인도

**구현 디테일**
- PC: 좌우 화살표 버튼 + 마우스 드래그 둘 다
- Mobile: 터치 스와이프만 (브라우저 native)
- 스크롤바 hidden
- 좌우 화살표는 섹션 헤더 우측에 배치 (오버레이 X) — 사용자 결정

**드래그 후 클릭 충돌 처리**
- `dragMoved > 3px`이면 click 이벤트 차단 (onClickCapture)
- 이 디테일을 빠뜨리면 카드 클릭이 의도치 않게 트리거됨

### 2-3. 시리즈도 캐러셀로 (모바일 일관성)

**문제**
시리즈 미리보기는 원래 그리드(3열)였음. 사용자 피드백:
- "mobile에서 height가 길어져서 UI 일관성이 깨지네"
- 모바일에서 시리즈 카드가 세로로 쌓여서 페이지 height가 폭증

**선택지**
- A: 그리드 유지 (시리즈가 늘면 캐러셀 검토)
- B: 캐러셀 적용 (PC 3개, 모바일 1.x개)
- C: 모바일만 캐러셀, PC는 그리드 (분기)

**결정: B (PC/모바일 모두 캐러셀)**

이유:
- 일관성: 최근 설교가 캐러셀이면 시리즈도 캐러셀
- PC에서도 시리즈가 늘어날 가능성 고려 (현재 3개 진행 중, 향후 5-10개로 늘면 그리드가 부적합)
- 분기(C)는 코드 복잡도 증가, 모바일/PC 디자인 통일성 저해

**카드 폭**
- PC: `calc((100% - 32px) / 3)` (정확히 3개, gap 16px)
- Mobile: 260px 고정 (1.3개 정도, 우측 잘림으로 더 있음을 암시)

**고려했지만 안 한 것**
- 시리즈 카드 폭이 더 작아지면 메타 정보를 thumbnail에 overlay 검토 — 결국 카드 폭이 충분해서 불필요

### 2-4. 진행 바 제거, 텍스트로 통일

**문제**
시리즈 진행 표시를 위해 4-5곳에서 progress bar를 사용했음. 사용자 피드백:
- 진행 바가 시각적 노이즈
- 시리즈는 "n / m" 진행률보다 "언제 시작해서 언제까지 + 몇 편 공개됐는지"가 본질
- placeholder 회차("곧 공개됩니다")가 UX를 어수선하게 함

**선택지**
- A: 진행 바 유지 + 숫자 표시
- B: 텍스트만 (진행 중 / 완료 명시 + 기간 + 편 수)
- C: 단순 카운트만 ("8편 공개")

**결정: B**

표기 형식:
- 진행 중: `2026.01.12 ~ 진행 중 · 8편` (진행 중 부분만 primary 색, 굵게)
- 완료: `2024.01.07 ~ 2025.12.28 · 26편` (전체 textSec, 일반)

**placeholder 회차 제거**
- 사용자가 명시: "곧 공개됩니다" 회차는 모두 제거
- 이유: 회차 목록은 "지금 볼 수 있는 것"만 보여줘야 명확. 미래 회차는 노이즈

**total 필드 처리**
- 데이터에는 남겨두되 UI에서는 사용하지 않음
- 시리즈의 "총 회차"는 알 수 없는 경우가 더 자연스러움 (계획이 바뀔 수 있음)

### 2-5. 검색 위치: 풀폭 → 사이드바 통합

**문제**
초기에는 전체 설교 페이지 상단에 풀폭(640px) 검색 input이 있었음. 사용자 피드백:
- 검색이 너무 크고 따로 떨어진 영역
- 좌측 필터 사이드바와 분리되어 있어 시선이 분산
- 풀폭 검색은 모바일에서는 자연스러우나 PC에서는 과함

**결정: 검색을 좌측 사이드바 최상단으로 통합**

구조:
```
사이드바 (240px, sticky)
├─ 헤더: 필터 + 초기화
├─ 검색 input
├─ 시리즈 (radio)
└─ 설교자 (radio)
```

이유:
- "필터링 + 검색"이 한 흐름 → 사이드바에 묶음
- 결과 영역이 더 넓어짐
- 모바일은 다른 패턴 (Search input + Filter icon 분리, 사용자 명시)

### 2-6. 검색 결과 피드백 UI

**문제**
검색을 했을 때 어떤 결과가 적용되었는지 알 수 없음. "총 N개 설교"만 표시되어 검색어가 사라지면 결과인지 전체인지 헷갈림.

**결정: 검색 활성 시 결과 영역 상단에 피드백 카드 추가**

```
🔍 "검색어" 검색 결과 · 12개    [검색어 지우기]
```

스타일:
- 배경 bg (다른 영역과 미세하게 구분)
- border-radius 8
- 우측에 "검색어 지우기" 미니 텍스트 버튼

또한:
- 결과 헤더의 "총 N개"를 검색 활성 시 "결과 N개"로 미세하게 변경

**모바일에도 동일 패턴**
- 더 컴팩트 (padding 10px 12px, fontSize 11.5)
- 길어지면 ellipsis

### 2-7. 시리즈 메타 카드: 큰 CTA → 미니 텍스트

**문제 (1차 디자인)**
시리즈 필터 선택 시 결과 영역 상단에 표시되는 메타 카드는 처음에 다음과 같았음:
```
[88x88 썸네일] [시리즈 제목 / 설명 / 메타]  [시리즈 상세 보기 →] ← 큰 primary 버튼
```

**사용자 피드백**
- 썸네일은 필요 없음 (시리즈 페이지에서 이미 시각화됨)
- "시리즈 상세 보기 →" CTA가 너무 큼
- 메타 카드 자체가 한 줄 정도로 컴팩트해야 함

**결정 (최종 디자인)**
```
SERIES · ON-GOING
시리즈명
설명 (1줄 클램프)
설교자 · 2026.01.12 ~ 진행 중 · 8편    [시리즈 상세 →]  ← 미니 텍스트 링크
```

이유:
- 시리즈 메타 카드는 "현재 필터 상태를 알려주는" 부가 정보 → 메인 컨텐츠인 결과 그리드를 압도하면 안 됨
- CTA는 텍스트 링크 형태로 충분 (chevron + 글자)
- 정보 밀도를 높임 (1줄 메타로 압축)

**모바일에도 동일하게 적용** — 시리즈 필터 선택 시 메타 카드 표시 (PC와 일관)

### 2-8. 메인 Featured: 외부 라벨 박스 제거

**문제 (1차 디자인)**
```
[surfaceAlt 배경 박스]
  THIS WEEK · 2026.05.05    [주일오전예배]  ← 외부 라벨 2개
  [영상 + 메타가 들어간 카드]
```

**사용자 피드백**
- 외부 라벨이 카드와 중복된 정보를 따로 보여줌
- 한 번에 카드만 보여주면 충분

**결정**
- 외부 라벨 박스 전체 제거
- 카드 한 장만 (영상 좌 + 메타 우)
- 시리즈 정보·날짜·service_type은 카드 내부 메타 라인으로 통합
- 섹션 헤더 "이번 주 설교" h2를 카드 위에 배치

이유:
- 정보 중복 제거
- 시각적 무게 감소
- 다른 섹션(최근 설교, 시리즈)과 일관된 구조 (섹션 헤더 + 컨텐츠)

### 2-9. Breadcrumb: "홈 > 말씀 > 설교" → "홈 > 설교"

**문제**
초기에는 3단계 breadcrumb이었음. 사용자 피드백: "말씀 단계 제거".

**결정**
- 단순화: `홈 > 설교` (설교 페이지 자체에서는 active)
- 하위 페이지는 `홈 > 설교 > 전체 설교` 또는 `홈 > 설교 > 시리즈 > {시리즈명}`

이유:
- "말씀"은 IA(정보 구조)상의 그룹이지만 사용자가 클릭하는 페이지가 아님
- 클릭 가능한 단계만 breadcrumb에 두는 게 명료

### 2-10. 모바일 모든 시리즈: 칩 → Search + Filter Icon + BottomSheet

**문제**
모바일 "모든 시리즈" 페이지는 처음에 칩(상태 필터: 전체/진행 중/완료) 패턴이었음. 사용자 피드백:
- 전체 설교 페이지와 일관성 없음 (전체 설교는 Search + Filter Icon)
- 칩만으로는 설교자/연도 필터 추가가 어색함

**결정: 전체 설교 모바일 패턴과 통일**

```
[Search input] [Filter Icon (44x44, 카운트 뱃지)]
  ↓ Filter 클릭
BottomSheet
├─ 드래그 핸들
├─ "필터" + 초기화
├─ 상태 섹션
├─ 설교자 섹션
├─ 연도 섹션
└─ "결과 보기" 버튼
```

이유:
- 두 페이지의 모바일 UX 완전히 동일
- 필터 늘어나도 BottomSheet는 수용 가능
- 칩은 작은 화면에서 옵션이 많으면 다단으로 흩어짐

### 2-11. 최근 설교 카드: 단독 설교 height 통일

**문제**
SermonCarouselCard는 시리즈 라벨이 있을 때만 렌더했음. 단독 설교(시리즈 없음)는 그 영역이 없어서 카드 height가 작아졌음.

**선택지**
- A: 시리즈 라벨 자리를 visibility: hidden로 빈 공간 유지
- B: 단독 설교에도 같은 위치에 다른 정보(service_type)를 표시

**결정: B**

표기:
- 시리즈 있음: `산상수훈 강해` (gold 색, letterSpacing 강조)
- 시리즈 없음: `주일오전예배` (textTer 색, 일반 letterSpacing)

이유:
- 두 정보 모두 사용자에게 유용 (어떤 시리즈인지 / 어떤 예배인지)
- height 통일 자연스럽게 해결
- 시각적 스타일은 다르되 같은 위치 = 정보 카테고리만 다르고 위치는 같다는 시각적 약속

### 2-12. 카드 내 gap 미세 조정

**문제**
"제목과 본문 말씀과의 gap이 너무 커"라는 피드백.

**원인 분석**
- 제목이 LineClamp 2 + minHeight 2.8em으로 빈 공간이 시각적으로 더 큰 gap처럼 보임
- 실제 marginBottom은 6px이었지만 빈 공간 포함하면 더 큼

**결정**
- 제목 marginBottom: 6 → 3
- 본문 말씀 marginBottom: 6 → 9 (메타와는 분리)
- 메타 영역 위에 border-top 추가로 정돈감

이유:
- minHeight를 유지하면서도 시각적 gap을 줄임
- 카드 정보 흐름이 더 빠르게 읽힘

---

### 2-13. 설교자 표기: 이름만 → 풀네임(역할 포함)

**문제**
최근 설교 카드에서 `preacherFullName(p).split(" ")[0]`로 이름만 표시했음. 즉 "김도현".

**사용자 피드백**
- 역할까지 같이: "김도현 담임목사"
- 한국 교회 컨텍스트에서 직책 표기가 자연스러움

**결정**
- 카드 메타에 풀네임 표시
- 날짜도 short(`05.05`) → full(`2026.05.05`)로

이유:
- 도메인 적합성: 한국 교회는 직책이 호칭의 일부
- 풀 날짜는 시간 맥락을 정확히 전달 (특히 시리즈 카드와 일관)

## 3. 디자인 원칙 (반복 적용된 것들)

### 3-1. Hover 3원칙

CSS hover 인터랙션에서 다음 세 가지를 지킴:

1. `transition: all` 금지 — 의도치 않은 속성까지 transition 걸리면 jank 발생
2. shorthand 대신 개별 속성 사용 — `border` 보다 `border-color`만 transition
3. hover 상태에서 `border` 자체를 명시하지 않음 — 두께가 바뀌면 레이아웃 시프트

```css
/* Bad */
.card { transition: all 0.2s; }
.card:hover { border: 1px solid #ccc; }

/* Good */
.card { transition: border-color 0.15s ease, box-shadow 0.15s ease; }
.card:hover { border-color: #E0DBD0; box-shadow: 0 4px 12px rgba(0,0,0,.05); }
```

### 3-2. 텍스트 미니멀리즘

진행 바, 외부 라벨 박스, 큰 CTA 버튼 등은 모두 "더 적은 시각 요소로 같은 정보를 전달"하는 방향으로 정리됐음. 사용자의 일관된 선호:

- 시각적 노이즈 줄이기
- 한 영역에서 한 가지 일만 함
- 부가 정보는 미니멀한 형태로 (텍스트 링크, 메타 라인)

### 3-3. height/위치 일관성

- 같은 그리드/캐러셀 안의 카드는 어떤 데이터 조합이든 같은 height
- 시리즈 라벨처럼 조건부 정보도 자리를 유지 (다른 정보로 채우기)
- 모바일/PC 양쪽에서 동일한 정보 구조

### 3-4. PC/모바일 디자인 통일성

같은 페이지의 PC와 모바일은 정보 구조가 동일하고, 레이아웃(grid vs stack)만 다름. 디바이스가 바뀐다고 사용자가 다른 UX를 학습할 필요 없음.

예외:
- 모바일은 사이드바 → BottomSheet
- 모바일 캐러셀은 좌우 풀폭 (페이지 padding 우회)

## 4. 데이터 결정

### 4-1. 시리즈명 유지 (산상수훈 / 다윗의 시편 등)

사용자가 명시: "데이터는 그대로 두고 UI만 변경". mockup 단계의 데이터 변경은 도메인 적합성보다 작업 비용을 늘리므로 유지.

### 4-2. SERIES_DATA / SERMONS_DATA 구조

DB 스키마(`sermons`, `sermon_series`)에 맞춰 mock 데이터를 구성. 특히:
- `series_id`, `series_order` (FK 관계)
- `is_active`, `started_at`, `ended_at` (시리즈 상태)
- `preacher` 객체 (`{ name, title }`)
- `is_featured` (이번 주 설교 식별)

이 구조 덕분에 데이터 → DB로 옮길 때 큰 변환 없이 사용 가능.

### 4-3. expandSermon 헬퍼

설교에 시리즈 객체를 join한 형태로 다루는 패턴. DB에서는 query join, mockup에서는 메모리 join. UI 컴포넌트는 항상 join된 형태로 받음.

## 5. 사용자 워크플로우 패턴 (배운 점)

### 5-1. 점진적 피드백, 큰 변경 → 작은 디테일

사용자는 큰 변경(예: 1280px로 확장)을 한 번에 결정하고, 그 다음 작은 디테일 7개씩 묶어서 피드백. 각 디테일은 명확한 표현("부담스러울 정도로 크다", "여백이 너무 길어진다", "UI 밸런스가 맞지 않는다")으로 지적.

대응 방법:
- 큰 변경 시 즉시 구현하지 않고 디테일 정리하는 단계를 거침
- 디테일을 표로 정리하고 추가 질문(A-E)으로 모호한 부분 확인
- 모두 답이 모이면 구현

### 5-2. 정형화/획일화 거부

"카드 디자인이 다 비슷하다" "필터가 다 같은 모양이다" 같은 피드백이 나오면 패턴이 도메인에 맞지 않는 신호. 도메인(교회, 설교 컨텐츠)에 적합한 형태로 재설계.

### 5-3. 통일성 강하게 추구

PC와 모바일이 다른 UX이면 즉시 지적. 같은 페이지 안에서도 시리즈 카드 디자인이 미세하게 다르면 일관성으로 통일.

### 5-4. 구현은 신중하게

"구현은 하지마"라고 명시하는 단계가 있음. 디테일 정리 → 결정 확정 → 구현 시작. 이 흐름을 지키지 않고 빨리 구현하면 다시 작업해야 함.

## 6. 트레이드오프 / 미해결 / 향후 검토

### 6-1. 시리즈 수가 늘어나면

현재 진행 중 시리즈 3개, 완료 시리즈 2개. PC 캐러셀은 3개 + 잘림 패턴이고 모바일은 1.3개. 향후 시리즈가 10개+로 늘면:

- 캐러셀 무한 스크롤은 자연스러움 (그대로 OK)
- 다만 "진행 중인 시리즈" 미리보기는 너무 길어질 수 있음 → 최대 6-9개 노출 + "모든 시리즈 →" 강조

### 6-2. 다국어

mockup은 한국어 고정. i18n 도입 시:
- 날짜 포맷 (`2026.05.05` vs `May 5, 2026`)
- 설교자 표기 (`김도현 담임목사` vs `Senior Pastor Kim`)
- letterSpacing — 한글에서는 자연스럽지만 영문에서는 너무 멀어 보일 수 있음

### 6-3. 영상 외 컨텐츠

현재 mockup은 YouTube 영상 위주. 추가 검토:
- 음성만(podcast) 설교
- 텍스트만 설교(설교문 PDF만 있는 경우)
- 라이브 스트리밍 진행 중 표시

### 6-4. 검색 고도화

현재 검색은 제목·본문 말씀·설교자 단순 매칭. 향후:
- scripture_text 본문 안에서 검색
- 한국어 분석기 (조사 제거, 어간 추출)
- 정렬: 관련도 순

### 6-5. 접근성 미완료

mockup 단계에서는 시각적 디자인 중심이라 다음이 미흡:
- 키보드 네비게이션 (캐러셀, BottomSheet)
- 스크린 리더 (aria-label, aria-live)
- 색상 대비 (gold + white 일부 영역)
- focus 표시

구현 단계(Phase 8-3 접근성 점검)에서 보강 필요.
